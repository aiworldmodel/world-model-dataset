## 结论与边界

目前主目录不能被严格表述为“391 个已核实开放、互不重复、直接服务世界模型的数据集”。项目保留了大量直接的动力学、动作条件转换与物理预测资源，但也混入静态感知、通用问答、几何资产、版本/子任务重复项，以及访问和身份尚未核实的资源。

本次逐条阅读了全部 391 条记录的描述与适用建议，并检查元数据、来源入口及明显同源关系。这是**覆盖全目录的记录级合规初审，加部分一手来源复核**，不是 391 篇论文和实际数据文件的最终认证。仅 4 条本次成功读取的一手页面在逐项 JSON 中标记 PRIMARY_PAGE_READ_THIS_AUDIT；其他条目明确为未重新逐源核验。其余联网复核遇到 429 限流，未把失败请求当成否定证据。

## 初心的可核查定义

依据 DATASET_RESEARCH_TODO.md 第 3、46、48 行，项目要求：
- 有状态/观测的时间转换、动作对齐转换、可用于未来预测的轨迹、反事实物理 rollout，或世界模型专用评测协议中的至少一种直接证据。
- 普通静态感知、分类、检测、分割、通用 VQA、纯模型资源，即使用于具身系统，也不能自动入选。
- 允许有可识别生成路径的官方生成工具，允许论文入口但必须明确访问未验证。
- 因此，不能额外要求所有数据都有动作，也不能一刀切排除生成器、轨迹或人体运动。
- “有视频”“能作先验”“能做预训练”“涉及机器人”不足以单独满足规则。多视角相机扫描尤其不等于物体动力学。
- README 的六类任务里包含静态3D重建和一般规划，范围比 TODO 的严格排除条款更宽。这是规则冲突，应先以严格证据门槛决定入选，再决定任务标签。

## 严重问题

### 1. 静态资源和一般感知越过门槛

- **Objaverse** (`objaverse`)：静态三维资产；丰富物体先验不等于状态转换数据。
- **EGAD!** (`egad`)：程序化物体几何和抓取难度；记录明确不含长时交互轨迹。
- **GraspNet-1Billion** (`graspnet-1billion`)：静态杂乱场景与抓取姿态标注；抓取可行性不是动作后果轨迹。
- **ContactDB** (`contactdb`)：接触区域先验；现有记录未提供时间转换或干预后果证据，且力方向描述需纠正。
- **HOPE Object Pose Dataset** (`hope-object-pose`)：静态物体姿态感知资源；现有记录无转换或预测协议证据。
- **BOP Benchmark** (`bop`)：六维姿态估计聚合基准；并非所需的世界模型诊断协议。
- **Orbis-Tabletop** (`orbis-tabletop`)：现有条目只描述桌面三维场景资产，未说明状态动作接口或轨迹生成路径。
- **TransBiolab** (`transbiolab`)：论文明确主要评测分割、深度和6D姿态；多视角扫描不等于物体状态演化。
- **MMR** (`mmr-reasoning`)：对象及部件推理分割，现有记录无状态转换、反事实rollout或专用WM评测。
- **Open3D-VQA** (`open3d-vqa`)：通用三维空间问答，现有记录无专用WM或未来状态评测。
- **EPIC-Bench** (`epic-bench`)：视觉掩码定位评测；具身任务名称不能替代状态转换证据。
- **HandEdit** (`handedit`)：人手图像到机器人本体的静态图像编辑；未记录跨时刻交互后果。
- **Teaching Monster Challenge** (`teaching-monster`)：教学视频生成和画像适配，未提供物理状态转换或世界模型诊断依据。
- **RoboVista** (`robovista`)：视觉问答和决策点标注本身不足；需另证未来状态/干预评测才可恢复。
- **DriveAction** (`driveaction`)：驾驶决策问答本身不足；未展示动作后果、未来状态或专用WM协议。
- **STU** (`stu`)：异常道路分割；现有收录说明仅为通用具身适用性。
- **MineInsight** (`mineinsight`)：多光谱感知数据；现有条目未证明时序预测或交互转换。

“建议移出”是对当前收录依据的判定，不宣称资源永久不可能用于世界模型。若新增可复现的转换数据或专用预测协议，可重新申请。

一手证据：
- [GraspNet](https://graspnet.net/) 明确描述 RGB-D 场景及物体/抓取姿态标注，不能由抓取姿态直接推导执行后的状态转换。
- [Objaverse](https://objaverse.allenai.org/) 是三维物体资产；可导入 Blender 不代表已提供动态数据。
- [TransBiolab 论文](https://arxiv.org/abs/2607.21071) 主要基准为分割、深度及6D姿态，多视角序列不是物体状态演化的充分证据。
- [4DSynth 论文](https://arxiv.org/abs/2608.26947) 描述程序化动态环境与导航任务，但原记录将来源同时标为 Real-world/Simulation、归入 WM 专用诊断，仍需重核类型、来源和可获取生成路径。

### 2. 重复、父集和历史版本导致数量失真

- `habitat-matterport-3d` → `hm3d`：相同 HM3D 主页及相同论文，条目描述同一数据集。
- `physion2` → `physion`：Physion2 记录复用 Physion 论文2106.08261；在找到独立第二版证据前不能作为独立项。
- `ego4d-v2` → `ego4d`：版本记录复用相同主页及论文，建议改为同一条目的版本。
- `ego4d-forecasting` → `ego4d`：父数据集的预测子任务，适合作为子集/协议而非独立采集库。

四条合并建议并不意味着可以机械地把总数减四：Physion2 若有真正独立版本应先补正确来源；Ego4D 预测协议可以保留为父记录下可检索子集。

另外需要关系建模而非直接删除的组：
- Bridge Data / V2、EPIC-KITCHENS-55 / 100、Virtual KITTI / 2：版本或扩展。
- Open X-Embodiment 与多个机器人子集、AMASS 与 HumanML3D/BABEL/KIT来源、D4RL 与 Kitchen/Adroit、RL Unplugged：来源/聚合重叠。
- Kubric / MOVi：生成工具与产物，不是简单重复。
- TrajNet / TrajNet++：现有共同仓库不足以证明两个独立数据入口。
- Ego-Exo4D 的代码链接复用了 Ego4D 仓库：需核对，但不能因此把两个不同项目合并。

### 3. 把可能用途写成已提供的能力

Kinetics、HMDB51 当前只以识别/视觉先验说明相关性；UCF101 确实常用于预测，但需具体预测切分。TAP-Vid、PoseTrack 的追踪估计可能可见目标时间帧，不能自动当作不可见未来预测。ScanNet/ARKitScenes 等需明确有序观测、位姿和任务范围；静态占据不等于未来占据。SocNav1 的“轨迹预测”描述需要优先核对。

没有动作不必排除；有动作标签不等于有执行器动作。机器人控制也不等于客观物理状态真值。应逐条保留字段层面的限制。

### 4. “开放”和元数据证据不足

- 59 条仅有 paper 链接。原规则允许，但不等于确认数据已公开。
- 65 条 access 英文说明包含待核验/确认/论文入口措辞（字符串筛查计数，非来源认证）。
- 127 条英文或中文许可说明显式含未知/待核验措辞（字符串筛查）。
- 98 条机构为 Authors and collaborators 或 project team 等占位形式。
- 85 条标记 2026 年；年份本身不是问题，但需检查实际发布版本。
- 317 条英文许可说明匹配 terms/research/consult 等宽泛词汇，这**不是**317条许可未知，不能这样宣传。
- 网页许可、代码许可、数据许可必须分开；有下载链接也不代表允许再分发或商用。

### 5. 维护流程不能证明学术合规

npm run check 只生成目录和检查 JavaScript 语法；git diff --check 只检查空白等补丁问题；HTTP 200 只证明入口可访问。它们都不会验证论文身份、内容、时间对齐、下载范围和许可。

历史 STRICT audit 的“全部保留”结论不能替代当前证据。TODO 的 Formal catalog: 52 已过时。README 宣称不是排名，但网站展示了391条星级评分（3星34条、4星237条、5星120条），未见本次可追溯的评分证据，不宜将星级当作质量验证。

## 整改顺序与验收

1. 主目录先隔离明确越界和重复项，并保留变更原因及旧链接重定向。
2. 资源类型至少区分固定数据、仿真环境/生成器、聚合库、评测协议和历史版本；前台计数不能全部统称独立数据集。
3. 每条增加严格证据：官方出处的具体位置、时间单位、输入输出字段、动作语义或可运行生成命令。无需全部具备，但须对应至少一条收录标准。
4. 记录数据访问与许可的验证日期和版本；未释放/未验证进入候选区，不与可下载正式条目混写。
5. 为每条增加父集/派生/包含/版本关系；相同来源不重复累计样本规模。
6. 建立可复现审核日志，取代用适用建议文案充当证据。189条保留候选也需要逐源审定，不能直接公布“严格通过189条”。
7. 审核完成前，应采用“391条资源记录，审核中”的准确口径，而非宣称391个全部合规开放数据集。
